# «Сквозь иголки» — редактирование каталога

Сайт полностью статический. Для просмотра дважды нажмите `index.html`. Сервер, база данных, установка библиотек и интернет для выполнения JavaScript не нужны. Для обновления ассортимента нужен только установленный Node.js; после генерации Node.js для просмотра сайта не требуется.

## Как добавить новое растение

1. Откройте папку `products`.
2. Создайте папку с постоянным именем, например `sosna-gornaya`. Используйте строчные латинские буквы, цифры и дефисы. Без пробелов, кириллицы и дефисов в начале/конце. Имя папки — идентификатор товара в ссылках и корзине; не меняйте его при изменении цены или названия.
3. Поместите фотографии в эту папку: `1.jpg`, `2.jpg`, `3.webp` и т. п. Поддерживаются JPG/JPEG, PNG и WebP. Генератор не изменяет фотографии.
4. Создайте там `product.json`. Можно скопировать файл существующего растения, удалить `legacyId`, изменить данные и список фотографий.
5. Заполните только известные сведения. Сохраните JSON в UTF-8. Используйте двойные кавычки; после последнего поля запятая не нужна.
6. Дважды нажмите `update-catalog.bat` в корне сайта. Альтернатива из терминала: `node tools/update-catalog.cjs`.
7. Если появились ошибки, исправьте указанный файл и повторите запуск. При ошибках проверки предыдущий каталог остаётся рабочим.
8. Откройте или обновите `index.html`. Обновите также уже открытые вкладки товаров, чтобы они получили актуальные данные.

Минимальный пример структуры файла (замените название, категорию и цену своими данными):

```json
{
  "name": "Название растения",
  "category": "Категория",
  "price": 1500,
  "currency": "RUB",
  "images": ["1.jpg", "2.jpg"],
  "tags": []
}
```

Не задавайте наличие и характеристики, если они неизвестны. Дополнительные поля:

| Поле | Значение |
| --- | --- |
| `availability` | `true` — «В наличии»; `false` — «Нет в наличии», добавление запрещено; отсутствует или `null` — статус скрыт |
| `height` | Высота/размер, строка |
| `size` | Уточнение размера и упаковки, если нужно. Показывается вместо `height` в краткой информации |
| `description` | Описание; переносы строк внутри строки записываются как `\n` |
| `tags` | Массив строк для поиска и фильтрации, например `["Для живой изгороди", "Хвойные"]` |
| `tag` | Необязательная короткая плашка на фото, например «Новинка» |
| `characteristics` | Объект характеристик, см. ниже |
| `order` | Число для явного порядка. Сначала товары с меньшим числом, затем без `order`; при равенстве — по русскому названию |
| `legacyId` | Только у восьми перенесённых товаров, для сохранения старой корзины. Новым товарам не нужен |

`price` — число без кавычек и знака рубля, например `1490` или `1490.50`. Поддерживается валюта RUB. `name`, `category`, `price`, `images` обязательны; `images` может быть пустым массивом, тогда показывается заглушка. Категории и фильтр тегов создаются автоматически по данным всех растений. Поиск учитывает название, категорию и теги. Категория, выбранный тег и поисковая строка работают совместно.

## Категории и наличие

Переключатель «В наличии» включён при каждом новом открытии или перезагрузке главной страницы. В этом режиме видны товары с `availability: true` и старые записи без поля `availability`. Записи с `availability: false` и явно неизвестным `null` показываются после отключения переключателя. Исходные JSON автоматически не меняются.

Категория, поисковая строка, тег и наличие применяются одновременно. Изменение любого фильтра сохраняет остальные. «Все категории» снимает только ограничение категории. Если подходящих растений нет, показывается «Растения не найдены».

Ссылка на категорию: `index.html?category=Туи#catalog` (браузер кодирует кириллицу в URL). Используйте этот формат для ссылок в меню и других блоках; ссылка с категорией на странице растения уже формируется автоматически. На главной переход между категориями сохраняет остальные фильтры и прокручивает страницу к каталогу. Кнопки браузера «Назад» и «Вперёд» восстанавливают категорию; переключатель, поиск и тег при этом не сбрасываются. Фильтры не сохраняются в localStorage.

Товары с `availability: false` видны только при отключённом фильтре, помечаются «Нет в наличии» и не добавляются в корзину, в том числе через прямой вызов функции добавления. Корзина исключает отсутствующие позиции, а перед копированием заказа повторно читает актуальное локальное состояние и очищает его от недоступных товаров. После изменения JSON по-прежнему нужно запустить генератор и обновить открытые страницы.

Дополнительные проверки фильтров находятся в `tests/catalog_filters.py` и запускаются общим браузерным сценарием: все категории и прямые ссылки, прокрутка и выделение, наличие по умолчанию и повторное включение, совместная работа фильтров, история переходов, недоступные товары и запрет их включения в заказ.


## Описание растения

В каждом `products/<slug>/product.json` предусмотрено поле `description`. Заполняйте его подтверждённым подробным описанием. У существующих растений, для которых описание не предоставлено, оставлена пустая строка; блок для них скрыт. Отсутствующее поле и строка из одних пробелов также не создают пустой блок.

Пример структуры (замените название, цену и описание своими данными):

```json
{
  "name": "Название растения",
  "category": "Категория",
  "price": 2490,
  "description": "Первый абзац с подтверждённым описанием растения.\n\nВторой абзац: дополнительные сведения.\nОтдельная строка внутри абзаца.",
  "images": ["1.jpg"],
  "tags": []
}
```

В JSON перенос строки внутри текста записывается как `\n`, а пустая строка между абзацами — `\n\n`. Двойные кавычки внутри описания экранируйте: `\"Смарагд\"`. Сам JSON-файл сохраняйте в UTF-8. Это обычный текст: HTML и Markdown не обрабатываются.

После изменения запустите `node tools/update-catalog.cjs` или `update-catalog.bat` и обновите страницу товара. Генератор переносит текст в `catalog.generated.js`; вручную этот файл редактировать не нужно. На странице описание появляется один раз, в блоке **«Описание растения»** под фотографиями и основной информацией, перед характеристиками. Длина текста не ограничивается интерфейсом, переносы строк сохраняются, длинные слова переносятся на мобильных экранах.


## Фотографии и характеристики

В `images` перечислите реальные имена файлов в нужном порядке. Первая фотография используется на карточке. На странице растения отображаются все фото; миниатюры и стрелки появляются при двух и более фотографиях. В полноэкранном просмотре работают стрелки, Escape и свайпы.

Пути считаются от папки конкретного товара: `"1.jpg"` означает `products/<slug>/1.jpg`. Допустимы вложенные папки: `"photos/2.webp"`. Не используйте `..`, абсолютные пути Windows или обратные слеши. Пробелы и кириллица в именах фото автоматически кодируются для URL, но проще использовать `1.jpg`, `2.png`, `3.webp`.

Существующие внешние ссылки `https://images.unsplash.com/...` сохранены в исходных восьми товарах. Генератор не скачивает их и не проверяет их сетевую доступность. Для перехода на локальные фотографии добавьте файлы в папку растения и замените ссылки их именами в `images`. Фото Unsplash и исходные шрифты Google требуют интернета; при недоступности фото появляется заглушка, шрифтов — системный шрифт. Полностью автономная работа с фотографиями требует собственных локальных фото.

В `characteristics` поддерживаются следующие ключи:

| Ключ | Поле |
| --- | --- |
| `species` | Вид растения |
| `variety` | Сорт |
| `height` | Высота |
| `crownDiameter` | Диаметр кроны |
| `growthRate` | Скорость роста |
| `frostResistance` | Морозостойкость |
| `lighting` | Освещение |
| `soil` | Почва |
| `care` | Особенности ухода |

Пустые значения не отображаются. Ключ `light` также поддерживается для совместимости, предпочтительный ключ — `lighting`. Неизвестные ключи генератор считает ошибкой, чтобы опечатки не скрывали сведения. Пример пустого шаблона:

```json
"characteristics": {
  "species": "",
  "variety": "",
  "height": "",
  "crownDiameter": "",
  "growthRate": "",
  "frostResistance": "",
  "lighting": "",
  "soil": "",
  "care": ""
}
```

Это поле внутри объекта товара, а не отдельный JSON-документ. Для восьми исходных растений перенесены только уже известные вид, сорт и высота. Описание, дополнительная агрономическая информация и наличие не выдумывались.

## Как изменить или убрать товар

- **Цена:** измените `price` в `product.json`, запустите обновление и обновите страницы браузера. Сумма корзины будет рассчитана по новой цене.
- **Нет в наличии:** задайте `"availability": false`, запустите обновление. Кнопки добавления отключатся; после обновления страниц товар исключается из корзины.
- **Новые фото:** добавьте файлы, измените `images`, запустите обновление. Изображения, не перечисленные в JSON, на сайте не показываются.
- **Удаление из каталога:** перенесите папку товара за пределы `products` либо удалите его `product.json`, затем запустите обновление. Сохранённая корзина пропустит удалённый товар без ошибки. Генератор сам папки и фото не удаляет.
- **Название:** измените `name`; имя папки оставьте прежним для стабильности ссылок и корзины.

## Структура и принцип работы

```text
products/
  index.json                       ← создаётся генератором
  tuya-smaragd/product.json         ← редактируется владельцем
  el-golubaya/product.json
  mozhzhevelnik-blue-arrow/product.json
  sosna-gornaya-mugus/product.json
  tuya-brabant/product.json
  el-obyknovennaya/product.json
  mozhzhevelnik-green-carpet/product.json
  sosna-kedrovaya/product.json
tools/update-catalog.cjs            ← генератор без сторонних пакетов
update-catalog.bat                  ← запуск двойным нажатием в Windows
catalog.generated.js               ← создаётся генератором
catalog.js                         ← подготовка данных, без списка товаров
cart.js                            ← связь страниц с общим хранилищем
cart-storage.html, cart-storage.js  ← общее локальное хранилище корзины
app.js                             ← карточки, поиск, фильтры, корзина
product.js                         ← сведения о растении и галерея
index.html, product.html            ← страницы сайта
styles.css, enhancements.css        ← сохранённый дизайн и дополнения
```

**Единственный редактируемый источник сведений о товарах — `products/*/product.json`.** Не редактируйте `products/index.json` и `catalog.generated.js` вручную: они перезаписываются генератором. JavaScript не содержит отдельного вручную поддерживаемого каталога.

Генератор сканирует подпапки с `product.json`, проверяет JSON, типы полей, slug и наличие локальных фотографий. Затем создаёт список slug в `products/index.json` и готовые данные с относительными путями в `catalog.generated.js`. Обе HTML-страницы загружают готовый JS обычным тегом `<script>`: `fetch()` не используется. На статическом хостинге работает тот же код. После изменения JSON всегда запускайте генератор; при публикации загрузите обновлённые исходные папки, сгенерированные файлы и остальные ресурсы сайта.

Ссылка на растение: `product.html?product=tuya-smaragd`. Карточки, включая похожие растения, используют обычные ссылки с `target="_blank"` и `rel="noopener noreferrer"`; добавление в корзину вкладку не открывает. Адрес `/products/tuya-smaragd/` не используется: для общего шаблона `product.html` он потребовал бы серверных правил маршрутизации или дополнительных сгенерированных HTML-страниц. Выбранный адрес работает напрямую через `file://`. Старые числовые ссылки `?id=1` больше не используются.

## Корзина между вкладками

Идентификатор позиции — slug папки. Количество ограничено 999 на позицию; повторное добавление увеличивает количество, уменьшение до нуля удаляет позицию. В хранении только slug и количество. Цены берутся из текущего каталога; неизвестные и недоступные растения пропускаются. Персональные данные не сохраняются и не отправляются.

Для согласованной работы через `file://` обе страницы загружают скрытый локальный `cart-storage.html`: он хранит корзину в своём `localStorage` под ключом `skvoz-igolki.cart.v2` и сообщает страницам об изменениях. Поэтому вкладкам не требуется доступ друг к другу или `window.opener`. Событие `storage` синхронизирует открытые вкладки, дополнительно состояние обновляется при возврате на вкладку. На статическом хостинге работает тот же механизм. Для миграции прежней числовой корзины учитывается ключ `skvoz-igolki.cart.v1` и сохранённые `legacyId`.

Браузер должен разрешать локальное хранилище и локальные вложенные страницы. Если хранение запрещено настройками браузера, показывается уведомление; временная корзина работает в пределах страницы, но сохранение и синхронизация недоступны. Проверка `file://` между вкладками выполнена в Microsoft Edge. После генерации обновляйте все вкладки, чтобы данные и наличие в них соответствовали новому каталогу.

Кнопка копирования формирует обычный текст для самостоятельной отправки продавцу. При отказе Clipboard API используется резервное копирование; если браузер запрещает и его, появляется выделенный текст для ручного копирования.

## Проверки для разработчика

- `node tests/catalog_check.cjs` — проверка генератора и полный браузерный сценарий с временной папкой товара, двумя локальными фото и JSON. Тестовая папка удаляется, рабочий каталог пересобирается до исходных восьми растений в блоке `finally`.
- `python tests/browser_check.py` — браузерная проверка существующего каталога; в среде проверки установлен Microsoft Edge и Python-пакет `websocket-client`. Это инструменты тестирования, для работы сайта они не нужны.
- Снимки: `tests/artifacts/product-desktop.png`, `tests/artifacts/product-mobile.png`.

Проверяются все восемь прямых slug-ссылок через `file://`, открытие карточки реальным кликом в новой вкладке, отсутствие `opener`, независимость кнопки корзины, синхронизация корзины между вкладками без перезагрузки, количества и суммы, текст заказа, поиск по названию и тегам, категории и теги, галерея, локальные фото, отсутствие товара в наличии и ширины 320/375/768/1024/1440 px. Неверный JSON и отсутствующее фото не перезаписывают рабочие результаты генерации.

## Корзина и заявка в Telegram

Настройки находятся в **`site-config.js`**:

```javascript
window.SHOP_CONFIG = {
  SITE_URL: '',
  TELEGRAM_USERNAME: 'Uliamel'
};
```

SITE_URL: https://skvoz-igolki-miv3dgeniy-7rsq.onreza.app/ (HTTPS). Автоопределение адреса при пустой настройке описано ниже.

`TELEGRAM_USERNAME` — контакт продавца без `@`, сейчас **Uliamel**. Изменение настройки применяется на главной и страницах растений после обновления вкладок. Для изменения этих двух настроек пересобирать каталог не нужно.

В корзине доступны:

- **«Отправить заказ в Telegram»** — перечитывает общую корзину, берёт актуальные названия, цены и наличие из загруженного каталога и открывает подготовленный текст для указанного продавца. В сообщении есть название каждого растения, количество, цена за штуку, сумма позиции, отдельная полная HTTPS-ссылка и общая стоимость. Одинаковые растения объединены по slug.
- **«Скопировать заказ»** — копирует тот же текст для ручной вставки. Если копирование запрещено браузером, появляется выделяемое текстовое поле с полным заказом.

Пустой `SITE_URL` не блокирует Telegram: HTTPS адрес определяется автоматически, file:// ссылки не добавляются.

Основной формат: `https://t.me/Uliamel?text=<encodeURIComponent(текст)>`. Он соответствует [официальной документации Telegram Deep Links](https://core.telegram.org/api/links#public-username-links). Вариант `tg://resolve?domain=Uliamel&text=...` также предусмотрен Telegram, но сайт использует HTTPS-ссылку, пригодную и для устройств без установленного обработчика `tg://`. Автоматическое переключение на `tg://` не выполняется. `t.me/share/url`, Bot API и токены не используются.

Telegram должен разрешать пользователю писать продавцу; поведение заполнения черновика зависит от клиента. Сайт только готовит текст и открывает чат, не отправляет сообщение и не определяет факт отправки. Покупатель проверяет сообщение и отправляет его самостоятельно. **Корзина после перехода в Telegram не очищается.**

При блокировке новой вкладки появляется отдельная ссылка «Открыть Telegram». Для длинного сообщения свыше 4000 символов сайт предлагает копирование целого заказа и ручную вставку, чтобы не полагаться на обрезание черновика клиентом Telegram. Это защитный порог сайта, а не универсальная гарантия лимитов всех клиентов; при необходимости заказ можно отправить несколькими сообщениями.

Постоянное хранение по-прежнему одно: `localStorage` файла `cart-storage.html`, ключ `skvoz-igolki.cart.v2`. В нём только slug и количества. Главная и страницы растений обращаются к этому общему хранилищу и через `file://`, и на HTTPS-хостинге. Дополнительная копия корзины в localStorage главной или в конфиге не создаётся. Обновление страницы, закрытие вкладки и штатное закрытие браузера не очищают корзину; восстановление зависит от разрешения браузера сохранять локальные данные. Приватный режим, запрет хранения, очистка данных сайта или перенос сайта на другой адрес/путь могут исключить восстановление. Названия, цены, ссылки и персональные данные в хранилище корзины не записываются.

Изменённые цены учитываются после пересборки каталога и обновления страниц. Снятые с продажи и удалённые позиции отбрасываются; повреждённые JSON-данные хранения, неизвестные slug и некорректные количества не ломают интерфейс. Перед подготовкой заказа корзина перечитывается и очищается от недоступных позиций.

Проверки:

- `python tests/cart_order_check.py` — сохраняет корзину в изолированном профиле, полностью перезапускает браузер, проверяет F5/Ctrl+F5, закрытие и повторное открытие вкладки, синхронизацию, текст и кодирование заказа, отсутствие ссылок при пустом адресе, резервное копирование, блокировку вкладки и мобильную вёрстку. Запускает тот же сценарий через `file://` и временный локальный HTTPS-сервер со статическими файлами. Требуются тестовые Python-пакеты `websocket-client` и `cryptography`, уже доступные в среде проверки; сайт их не использует.
- `node tests/catalog_check.cjs` — прежние проверки генератора, фильтров, галереи, корзины и изменения цены/наличия.

HTTPS-сервер и временный сертификат используются только тестом и удаляются после него; для сайта серверное приложение не добавлено. Навигация в Telegram в тестах подменена: проверяются адресат и полный URL, реальные сообщения и запросы к чату продавца не отправляются. Автозаполнение в конкретном установленном клиенте Telegram этими тестами не подтверждается.

Основные файлы: `site-config.js` — настройки; `order.js` — форматирование и действия с заказом; `app.js` — текущая корзина и кликабельные названия; `index.html`/`product.html` — одинаковые кнопки корзины; `enhancements.css` — оформление и мобильная адаптация. Существующие `cart.js`, `cart-storage.js` и `cart-storage.html` остаются единым механизмом хранения.

Кнопка Telegram синхронно резервирует окно в обработчике клика, затем перечитывает корзину и переводит уже открытое окно на `https://t.me/<контакт>?text=...`. Открытие окна не откладывается до завершения асинхронного чтения хранилища. При пустом SITE_URL на HTTPS база ссылок берётся из location. Корзина не очищается.

## Кнопки товаров и уведомление корзины

Кнопки в каталоге, в похожих растениях и на странице товара показывают состояние общей корзины. Если позиции нет, надпись — «Добавить в корзину»: нажатие добавляет одну штуку. Если количество больше нуля, надпись — «Удалить из корзины»: нажатие удаляет всю позицию, независимо от количества. Для изменения количества используйте `+` и `−` внутри корзины. Товары без наличия всегда показывают недоступную кнопку «Нет в наличии».

Состояние надписи, оформления и `aria-pressed` вычисляется из текущего количества по slug; отдельного сохранённого состояния кнопок нет. Команда `toggle` дополняет существующее общее хранилище `cart-storage.html` и не меняет ключ `skvoz-igolki.cart.v2`. Краткая блокировка повторного действия на 500 мс защищает от двойного нажатия; она не хранит информацию о наличии позиции в корзине. События общей корзины обновляют кнопки во всех вкладках и после загрузки страницы.

После добавления показывается «Товар добавлен в корзину» и кнопка «Перейти в корзину». Нажатие на уведомление или его кнопку вызывает ту же `openCart()`, что и кнопка в шапке. Кнопка уведомления работает с Enter и Space. Уведомление исчезает примерно через 4 секунды; наведение и фокус приостанавливают таймер. При открытии корзины уведомление скрывается. Обычные сообщения, например об успешном копировании заказа, при открытой корзине выводятся внутри неё.

Проверка новых сценариев: задайте переменную окружения `SKVOZ_ORDER_SCENARIO=cart_interaction_scenarios.py` и запустите `python tests/cart_order_check.py`. Сценарий проверяет одинаковую реализацию через `file://` и временный HTTPS-хостинг, включая перезапуск браузера, синхронизацию, удаление всей позиции, быстрые нажатия, клавиатуру, таймер, мобильные размеры и оформление заказа. Переменная предназначена только для тестов. Обычная команда `python tests/cart_order_check.py` продолжает проверять сохранение корзины и подготовку Telegram-ссылок. Реальные сообщения продавцу в тестах не отправляются.

## Отмена последнего удаления

После удаления всей позиции кнопкой товара или уменьшения последней штуки до нуля появляется «Товар удалён из корзины» и кнопка **«Вернуть»**. Восстанавливается количество непосредственно перед удалением, а не одна штука. Обычное уменьшение количества, при котором позиция остаётся в корзине, не считается удалением позиции.

Используется одно существующее уведомление. На странице оно остаётся всплывающим; при открытой корзине уведомление удаления размещается внутри её панели, чтобы кнопка была доступна и с клавиатуры. Уведомление добавления по-прежнему открывает корзину. Нажатие на текст уведомления удаления ничего не восстанавливает и не открывает; действие выполняется только кнопкой «Вернуть».

Срок отмены — 5 секунд. Наведение или фокус приостанавливают таймер. Кнопка × закрывает уведомление и отменяет возможность восстановления. Новый показ уведомления заменяет прежний; хранится только один снимок `{slug, quantity}` в памяти страницы. Снимок не записывается в localStorage и теряется при перезагрузке. Восстановленная корзина, как и раньше, сохраняется между посещениями.

Количество для снимка возвращается из общего хранилища в момент удаления. Перед восстановлением хранилище заново загружает локальный `catalog.generated.js` с параметром против кеширования; `fetch()` не используется. Поэтому работает и открытие через `file://`. Удалённые из каталога и недоступные товары не восстанавливаются. При успешной проверке цена соответствующего растения в памяти страницы обновляется из свежего каталога; снимок не содержит старой цены. Если сам каталог не удалось загрузить, операция отклоняется с отдельным сообщением.

Команда `restore` изменяет то же хранилище `skvoz-igolki.cart.v2`, а не отдельную корзину. Восстановление возможно только при отсутствии позиции в момент выполнения операции. Если её уже добавили вручную или в другой вкладке, существующее количество сохраняется. Кнопка блокируется на время восстановления, снимок расходуется до асинхронного запроса, повторные нажатия не увеличивают количество. Если за это время произошло новое удаление, его уведомление не заменяется результатом более раннего восстановления.

Изменения общей корзины выполняются под общим Web Lock там, где браузер его поддерживает. В остальных браузерах действуют проверки текущего состояния и блокировки страницы. Обновление корзины и кнопок между вкладками продолжает использовать существующие сообщения и событие `storage`.

Проверка: `python tests/cart_undo_check.py`. Тест создаёт временную копию статического сайта и отдельные профили браузера, затем проверяет `file://` и HTTPS, количества 1/5, все места удаления, несколько последовательных удалений, повторное восстановление, ручное добавление и изменения из другой вкладки, изменение цены, недоступность/удаление товара, таймер, клавиатуру и мобильные размеры. Рабочие `products/*/product.json` и `catalog.generated.js` не меняются. Для тестового HTTPS применяются прежние тестовые Python-инструменты; для работы сайта зависимости и серверное приложение не нужны.

## Публичные ссылки в Telegram-заказе

Текущий публичный адрес: `https://skvoz-igolki-miv3dgeniy-7rsq.onreza.app/`. В `site-config.js` он уже задан как `SHOP_CONFIG.SITE_URL`.

`publicSiteUrl()` читает конфигурацию в момент формирования заказа:

1. Корректный явно заданный HTTPS-адрес имеет приоритет над адресом открытой страницы. Его домен и подпапка сохраняются.
2. Если значение пустое или конфигурация ещё отсутствует, при открытии через HTTPS используется адрес текущей страницы с её подпапкой размещения. Например, для `/shop/product.html?product=...` корнем ссылок становится `/shop/` на том же HTTPS-хосте. Поисковые параметры и якорь страницы в базу не попадают.
3. При открытии через `file://` без настроенного публичного адреса ссылки в сообщение не добавляются. Заказ по-прежнему можно подготовить и отправить через Telegram.
4. Явно заданный некорректный или не-HTTPS адрес не используется. Исправьте его либо очистите поле, чтобы включить автоматическое определение на HTTPS.

Для каждого растения `publicProductUrl()` объединяет публичную базу с существующим `productUrl(product)`, использующим slug. В сообщение добавляется отдельная строка `Ссылка: https://skvoz-igolki-miv3dgeniy-7rsq.onreza.app/product.html?product=<slug>`. Затем весь текст кодируется в параметре `text` Telegram URL. Встроенные цены, названия и количество берутся из обычной корзины; в localStorage ссылки не сохраняются.

В обеих HTML-страницах сохранён порядок классических `defer`-скриптов: конфигурация раньше `order.js`, затем `app.js`. К URL `site-config.js` и `order.js` добавлен параметр версии `v=order-links-20261026`, чтобы при обновлении HTML браузер запросил новые URL скриптов. При дальнейшей замене конфигурации/логики обновляйте версию либо используйте корректные правила кеширования на хостинге. Просмотр правильного файла `site-config.js` по прямому адресу сам по себе не показывает, какое значение уже выполнялось в открытой вкладке.

Проверка: `python tests/order_links_check.py`. Тест использует временную копию сайта и проверяет обе страницы через `file://`, HTTPS в корне и HTTPS в подпапке. Проверяются доступность конфигурации в момент вызова `buildOrder()`, приоритет заданного адреса, поздняя/пустая конфигурация, абсолютная ссылка для каждой позиции, несколько растений и обратное декодирование кириллицы/переносов строк из Telegram URL. Рабочий каталог не меняется; реальных запросов к Telegram нет.

Опубликованный сайт в среде проверки недоступен (`ERR_NETWORK_ACCESS_DENIED`). Локально с корректным `window.SHOP_CONFIG.SITE_URL` ссылки формировались и до изменения. Воспроизведённый дефект старой функции — возврат `null` при пустом значении даже на HTTPS; из-за этого условие `if (base)` пропускало строки ссылок. Кеш или отсутствие выполнения конфигурации на опубликованной странице без её фактических runtime-данных не подтверждены.


### Компактный каталог и очистка корзины

На смартфонах до 767 px каталог и похожие растения показываются в две колонки; высота скрыта только в карточках. Категории и теги прокручиваются отдельно от страницы, переключатель наличия остаётся справа. Изображение hero показывается целиком; на смартфонах текст находится под ним.

«Очистить корзину» открывает подтверждение внутри существующей корзины. После подтверждения хранилище выполняет одну операцию `clear`, сохраняет пустую корзину и синхронизирует вкладки. Повторное нажатие блокируется. Массовая очистка не создаёт снимков отмены; «Вернуть» для удаления одной позиции работает по-прежнему.

Проверка: `python tests/responsive_check.py` — девять ширин 320–1440 px, отсутствие переполнения, компактные уведомления, категории/теги/наличие, отмена подтверждения и атомарная очистка, обновление второй вкладки и сохранение после перезагрузки через file:// и локальный HTTPS. `python tests/cart_undo_check.py`, `python tests/cart_order_check.py`, `python tests/order_links_check.py` и `node tests/catalog_check.cjs` проверяют остальные сценарии. Реальные сообщения Telegram не отправляются.
